# 에이전트 페이지 업그레이드 계획 (개인 앱)

> 상태: 2026-11-13. 이 문서는 구현으로 바뀌어 더 이상 계획을 담지 않는다. 앱은 개인 에이전트를 **봇**이라 부르며 Push Bot 하나와 회사마다 봇 하나로 만들었다. 계약은 [api-spec.md](api-spec.md) 3.17, 화면과 동작은 [feature-spec.md](feature-spec.md) 15장, 제품 규칙은 [PRD.md](PRD.md) 7.5를 따른다.
> 원문 요청과 영상 자료: `push-design/work/agent-upgrade/` (OWNER-REQUEST.md, video/).

## 이 계획에서 실제와 달라진 것

- 상태 줄: 이벤트에서 상태를 지어내지 않는다. 서버가 `status` 프레임에 `phase`, `since`, `ahead`를 실어 보낸다(api-spec 3.3). 예전 "채팅 상태에 서버 변경 없음" 절은 폐기한다.
- 봇 색: 회사마다 정해진 색이 아니라 이용자가 11가지에서 고르거나 서버가 정한다(`color`). `avatarKey`와 `mascotKey`는 없다.
- 회사 이름 입력: 없다. 봇은 항상 공고에서 만들고(`POST /bots`의 `postingId`), 같은 회사로는 봇이 하나뿐이다.
- 대화: 봇에는 대화가 하나이고 첫 보내기가 만든다. 새 대화 만들기와 `GET/POST /bots/{id}/conversations`는 없다. 봇이 생기기 전의 대화는 그대로 두고 웹의 대화 목록에만 나온다.
- 자료: `GET /materials`가 서류·북마크·링크를 한 곳에서 준다. `GET /bots/{id}/library`는 없다.
- 지우기: 봇을 지우면 대화와 작업 기록이 연쇄로 지워진다. 소프트 삭제가 아니다.
- 첫 진입: 총괄 봇 온보딩이 아니라 채팅 첫 화면의 퀵스타트 칩이다(Push Bot 13개, 회사 봇 4개).

웹과 데스크톱은 에이전트라는 이름과 대화 목록을 그대로 쓴다.
