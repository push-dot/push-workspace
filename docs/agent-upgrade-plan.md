## C. 모션·상태 명세 (세 갈래)

공통 상태 매핑 함수 `stateOf(events)`를 쓴다. 하나의 순수 함수로 만들고 단위 테스트로 전부 덮는다. 이벤트 출처는 `push-be/packages/contracts/spec/conversations.ts` `chatEvents`와 `push-fe/packages/api-client/src/types.ts:280-387`이다.

| 상태 | 바뀌는 서버 이벤트 |
|---|---|
| 대기 | 진행 중 작업 없음 |
| 생각 중 | 전송 직후, 큐 대기(queuePosition), `status`, `think`, `plan` |
| 작업 중 | `tool`(run/ok), `todo`, `diff`(승인 밖), `paper`, `file`, `fit`, `token`(답변 쓰는 중) |
| 도움 필요 | `approval`, `choice`, `tool`(state=wait), `done.awaiting` |
| 완료 | `done`(awaiting 없음), `result` |

- `error`와 `cancelled`는 상태가 아니라 종료 신호로 처리한다.
- 우선순위는 도움 필요 > 작업 > 생각이다.
- 300ms 디바운스로 생각 ↔ 작업이 깜빡이지 않게 한다.

### C-1. 에이전트 홈 아바타 모션 (5상태, 여기서만 전부 사용)
- **입력:** 서버 목록 DTO의 `liveState`(idle/thinking/working/needs_help/done_unread)다. 서버가 활성 작업의 마지막 chat_event와 읽음 시각으로 계산한다(D-3).
- **갱신:** 에이전트 홈에 포커스가 있고 진행 중인 봇이 있을 때만 3초 간격으로 다시 받는다.

| 상태 | 부품 움직임 (몸통, 귀퉁이, 눈 L/R, 넥타이) | 반복 |
|---|---|---|
| 대기 | 정지(목록에서는 깜빡임도 없음) | 없음 |
| 생각 중 | 눈이 가늘어지고(scaleY 0.45) 위·오른쪽으로 쏠림(translate 3,−2). 귀퉁이가 천천히 접혔다 펴짐(rotate 0→−12°) | 1.6초 루프 |
| 작업 중 | 눈이 좌우로 훑음(translateX ±3). 넥타이가 흔들림(rotate ±8°, 위 고정점). 몸통이 1px 통통 | 0.9초 루프 |
| 도움 필요 | 눈이 커지고(scale 1.15) 정면을 봄. 몸통이 두 번 작게 흔들림(±4°) 후 1.5초 쉼. 주황 점 배지 | 2.5초 루프 |
| 완료(안 읽음) | 한 번 통 튀고(spring) 눈이 웃는 호로 바뀐 채 유지. 사용자가 그 봇을 열면 대기로 돌아감 | 1회 + 정지 표정 |

- **전환:** 상태가 바뀌면 루프를 멈추고 160ms에 원위치로 돌아간 뒤 새 상태를 시작한다.
- **성능:**
  - 보이는 행만 움직인다(FlatList viewability).
  - 동시에 움직이는 아바타는 최대 6개다.
  - 포커스를 잃거나 백그라운드로 가면 정지한다.

### C-2. 채팅 헤더 불빛 (로고는 정지)
- **위치:** 헤더 가운데 마스코트(36)의 오른쪽 아래에 지름 10 점을 둔다. 배경색 2px 테두리를 두르고, 마스코트와 겹친다.

| 불빛 | 켜지는 조건 | 꺼지는 시점 |
|---|---|---|
| 초록 | 이 봇의 새 메시지가 도착함 | 사용자가 맨 아래까지 본 순간에서 1초 뒤 꺼진다. 이미 맨 아래면 2초 켰다 끈다. 우선순위는 빨강보다 낮다. |
| 빨강 | 이 봇을 쓸 수 없는 제한 상태 | 제한이 풀리면 꺼진다(충전, 플랜 변경, 계정 재조회). 점을 누르면 기존 크레딧 없음 안내(ChatNoCredit 보드)가 열린다. |

초록이 켜지는 '새 메시지 도착':
- 답변 `done`
- 총괄 봇이 위임한 결과가 회사 봇 대화에 들어온 경우
- 화면 밖에서 온 메시지를 대화를 열 때 받은 경우

빨강이 켜지는 '제한 상태':
- 크레딧 0
- 서버가 크레딧·한도 오류로 전송을 거절함(오류 코드는 PR8에서 확인)

공통 규칙:
- 불빛이 켜지거나 꺼질 때 opacity 160ms만 쓰고 그 밖의 모션은 없다.
- 불빛과 상태 UI는 독립이다. 불빛은 "새 메시지/제한"만 말하고 진행 상태는 말하지 않는다.
- 접근성: 헤더 라벨에 "새 메시지 있음" 또는 "크레딧 부족"을 덧붙인다.

### C-3. 채팅 봇 상태 UI (중간 과정 대체)
- **모양:** 대화 맨 끝, 봇 말풍선 자리에 한 줄을 둔다. 구성은 [움직이는 로고 24][현재 상태 문장 + 경과 시간][중지]다.
  - 상태 문장은 마지막 의미 있는 이벤트의 요약이다(예: "생각하는 중…", "공고를 읽는 중…", "이력서를 고치는 중…").
  - tool `summary`와 status 동사를 그대로 쓴다.
  - 이 로고만 C-1의 생각/작업/도움 필요 모션을 쓴다.
- **보이는 동안:** 전송 직후부터 답변 완료(`done`), `error`, `cancelled`까지다. 끝나면 160ms 페이드로 사라지고 최종 답변만 남는다.
- **도움 필요일 때:** 상태 UI는 "확인이 필요해요"로 남는다. 응답 카드는 별개로 남는다.
  - 승인/선택 카드(`ApprovalPanel`, DOCUMENT_EDIT diff 포함)는 지금처럼 입력창 자리에 그대로 둔다.
  - 사용자가 응답하면 상태 UI가 생각 중으로 돌아간다.
- **대체·제거되는 것:**

| 기존 | 처리 |
|---|---|
| 입력창 위 ✻ `StatusRow`(회전 글리프, 동사, 경과, 중지) | 제거. 동사·경과·중지는 상태 UI로 옮김 |
| "생각함 · N초"(think) | 제거 |
| plan(strategy/feedback) 카드 | 제거 |
| `ToolLine`(상태 점, action/target, ⎿ 결과, +N줄) | 제거 |
| todo 목록 | 제거 |
| 승인 밖 diff | 제거 |
| worked "N초 동안 작업했어요" / Working 블록 | 제거 |

- **서버 변경:** 없다. 이벤트는 그대로 오고, 클라이언트 reducer가 화면용 목록에서 거른다.

### C-4. 구현 원칙 (세 갈래 공통)

**2차 지시(계획 검토 중, 1차 '모션 위치'를 대체):**
1. 5상태 모션은 에이전트 홈 봇 목록 아바타에서만 한다.
2. 채팅 헤더 가운데 로고는 움직이지 않는다. 새 메시지가 오면 초록 불, 크레딧 소진 같은 제한이면 빨강 불이다. 조건, 꺼지는 시점, 위치는 계획 담당이 제안한다.
3. 채팅의 중간 메시지(think/plan/tool/todo 등 진행 과정)를 봇 상태 UI로 바꾼다.
   - 현재 상태 하나만 보여 준다.
   - 왼쪽에 봇 로고를 두고, 이 로고만 움직인다.
   - 답변이 완료되면 사라진다.

가정 트리 (검증 상태):
- "회사 = 기업 회원 계정"은 아니다. 사용자가 적은 문자열이다(검증, 코드).
- "봇 = 새 엔티티"는 필요 없다. 대화 1개 = 봇이다(오너 답으로 성립).
- "동의를 옮기면 법적 기록이 바뀐다"는 해당 없다. 참고 데이터 동의만 옮긴다(오너 답).
- "로고를 새로 그려야 한다"는 아니다. 기존 마스코트가 이미 부품 구조다(검증, SVG).
- "진행 과정을 다 보여 줘야 신뢰한다"를 뒤집었다. 오너가 현재 상태 하나만 보이게 하라고 했다. 대신 사용자가 응답해야 하는 승인/선택 카드는 남겨 통제권을 지킨다.

Contrarian: "사용자는 대화 기록을 원한다"를 뒤집어, 회사별 기억이 기록보다 중요하다고 본다. 오너가 기존 기록 전부 삭제로 확인했다.

### F-2. 모호성 보고서 (02-ambiguity-report.md)

### F-3. Seed 명세 (03-seed-specification.md)
- **목표:** 구직자가 회사별로 기억하고 일하는 에이전트를 한눈에 다루게 한다. 이를 위해 에이전트 탭을 총괄 봇 + 회사 봇 목록 구조로 바꾼다. 봇 상태는 목록에서는 마스코트 모션으로, 채팅에서는 현재 상태 한 줄과 헤더 불빛으로 보여 준다.
- **In:** R1~R16 전부.
- **Out:**
  - 기업 에이전트, fo-desktop, 가입 약관 화면
  - 액세서리·몸통 모양 변형, 헤더 로고 모션
  - 진행 과정 펼쳐 보기
  - 기존 대화 이관
- **온톨로지:**

| 개념 | 정의 |
|---|---|
| 총괄 봇 | 사용자당 1개인 chief 대화 |
| 회사 봇 | (사용자, 정규화 회사명)당 1개인 company 대화 |
| 대화 | 봇 하나의 끝없는 한 줄 |
| 위임 | 총괄 봇이 회사 봇 대화에 작업을 넣고 결과를 받는 것 |
| 봇 상태 | 대기, 생각 중, 작업 중, 도움 필요, 완료 |
| 봇 상태 UI | 채팅 끝의 현재 상태 한 줄. 로고만 움직이고 완료되면 사라짐 |
| 헤더 불빛 | 초록(새 메시지), 빨강(제한) |
| 자료 | 서류(업로드 파일, Push 서류), 북마크(공고), 링크 |
| 에이전트 홈 | 옛 사이드바. 에이전트 탭 루트 |
| 온보딩 | 총괄 봇 첫 대화. 참고 데이터 동의가 기록되면 끝 |

- **Near-miss:**
  - 회사 봇의 회사는 `companies`, `applications.company`와 다르다.
  - 자료 모달은 `@` 멘션, `/materials` 첨부 시트와 다르다. 둘은 남는다.
  - 봇 상태 UI는 승인/선택 카드와 다르다. 카드는 남는다.
  - 헤더 불빛은 진행 상태를 말하지 않는다.
- **성공 기준:**
  - 5상태가 서버 이벤트대로 바뀐다. 매핑 단위 테스트로 전부 덮는다.
  - 채팅에 중간 과정 항목이 0개다(실시간과 다시 열기 모두).
  - 상태 UI는 완료, 오류, 중지 때 사라진다.
  - 헤더 로고는 정지이고, 불빛 규칙 2개가 지켜진다.
  - 모션 중 60fps, JS 스레드 0이다.
  - 동작 줄이기가 켜지면 루프가 0이다.
  - 버튼 5종이 같은 44 원이다.
  - 보드와의 시각 결함이 0이다.
  - iOS gate가 정확한 head에서 전부 통과한다.
  - 동의는 기존 API로 기록되고, 동의 전에는 에이전트 호출이 막힌다.

### F-4. Claude Design 요청 보드 ("Push 앱" 먼저, ego lite로 요청)
1. **AgentHome:** 에이전트 탭 첫 화면(옛 사이드바)이다.
   - 헤더: 왼쪽 프로필 사진, 오른쪽 + 버튼. 둘 다 뒤로가기와 같은 44 원 Glass 버튼이다.
   - 목록: 총괄 봇이 맨 위에 고정되고, 그 아래 회사 봇 목록이다. 행은 회사 색 마스코트(상태 표정), 회사명, 마지막 메시지 한 줄, 시간이다.
   - 탭바 바로 위: [자료 44][긴 검색 인풋].
   - 상태 화면: 회사 봇 0개, 검색 결과 없음, 길게 눌러 삭제 메뉴와 확인.
   - iOS/Android, 라이트/다크.
2. **AgentOnboarding:** 총괄 봇 첫 대화다.
   - 환영 말풍선
   - 참고 데이터 동의 카드(필수, 전문 보기, 동의 버튼)
   - 선택 단계 카드(이력서 올리기, 관심 직무 칩, 건너뛰기)
   - 동의 전 입력창 잠김
3. **CompanyBotNew:** + 버튼 시트다.
   - 회사 이름(필수), 공고 링크(선택)
   - 중복 회사 안내와 이동
   - 플랜 한도 도달 시 업그레이드 안내
4. **ChatBotHeader:** 회사 봇 채팅 헤더다.
   - 구성: [뒤로 44][가운데: 정지된 회사 색 마스코트 + 회사명][⋯ 44]
   - 마스코트 오른쪽 아래 상태 불빛 3가지: 없음, 초록(새 메시지), 빨강(크레딧 소진·제한)
   - 빨강을 누르면 열리는 안내(기존 ChatNoCredit 연결)
5. **ChatBotStatus:** 대화 끝 봇 상태 UI다.
   - 구성: [움직이는 로고 24][현재 상태 문장 + 경과][중지]
   - 상태 3가지: 생각 중, 작업 중(도구 요약 문장), 도움 필요
   - 도움 필요 상태에서는 입력창 자리의 승인/선택 카드와 함께 둔다.
   - 큐 대기 상태
   - 답변 완료 뒤 사라진 상태(최종 답변만 남음)
   - 중간 과정(생각함, 툴 줄, todo, 작업 시간)이 없는 대화 화면 전체
6. **MaterialsModal + MaterialDetail:**
   - 위쪽 토글 navbar: 전체/서류/북마크/링크
   - 카테고리 묶음 무한 리스트, 행 오른쪽 '채팅에서 쓰기'
   - 하단 폭 100% 검색
   - 빈 화면, 검색 결과 없음, 로딩
   - 상세 시트(종류별 이동 버튼, 휴지통 44 → 삭제 prompt)
   - 봇 고르기 시트
7. **MascotStates:** 에이전트 홈 아바타 5상태와 채팅 상태 UI 로고 3상태다.
   - 상태별 키프레임 3장과 C-1 표 첨부
   - 크기: 목록 40, 상태 UI 24, 헤더 36(정지 + 불빛)
   - 회사 색 예시 4개, 다크 모드, 동작 줄이기 정지 프레임
8. **웹:** 앱 구현이 끝난 뒤 "Push 웹"에 1, 4, 5, 6을 데스크톱 폭으로 요청한다.

## G. 위험과 열린 질문
- **오너에게 남은 질문은 없다.** 마감 일정만 정해지지 않았다.
- **위험: 기존 대화 삭제는 되돌릴 수 없다.** staging에서 먼저 하고 스냅샷을 만든다. prod는 릴리스 단계에서 오너가 확인한다. PR5에서 Push 서류와 지원이 남는지 검증한다.
- **위험: 중간 과정이 사라진다.** 사용자는 에이전트가 무엇을 했는지 덜 본다. 위험한 행동은 승인 카드가 남으므로 통제권은 유지된다. 작성된 서류(paper)와 결과 카드도 남는다.
- **위험: 동의 이력 테이블이 없다.** `user_consents`는 현재 상태만 남긴다. 이번 범위 밖이고, 법무 REVIEW-NEEDED에 남긴다.
- **위험: 목록 liveState는 폴링이다.** 포커스가 있고 진행 중인 봇이 있을 때만 3초 간격으로 받는다.
- **위험: 크레딧 제한 오류 코드가 계약에 없다.** 계약의 error.code는 NOT_CONFIGURED/PROVIDER_ERROR/INTERNAL뿐이다. PR8에서 전송 거절 응답을 확인한다. 없으면 PR1에 `CREDITS_EXHAUSTED`를 더한다.
- **보드가 C절과 다르면 보드를 따른다.** 보드가 없는 부분만 C절을 따른다.
