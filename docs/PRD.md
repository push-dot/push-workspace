- 상태: 초안

## 1. 개요

Push는 근거 수집부터 문서 작성, 지원, 면접, 오퍼까지 구직 과정 전체를 한 작업공간에서 관리한다. 흐름은 `탐색 → 역량 보완 → 문서 생성 → 지원 → 면접 → 오퍼`다.

v2는 기존 데스크톱 앱(macOS·Windows)을 그대로 두고 **iOS·Android 모바일 앱을 추가**한다. 두 클라이언트는 같은 계정과 같은 백엔드 API를 쓴다. 대화, 지원, 이력서 파일, 공고는 양쪽에서 함께 보인다.

| 클라이언트 | 역할 |
|---|---|
| 데스크톱 (Tauri) | 깊이 있는 작업: 문서 편집·확정·출력, 역량 보완 프로젝트(CLI), 캘린더, 설정(개인 결제는 모바일 인앱 결제만). Career Vault와 면접 준비는 추후 |
| 모바일 (Expo) | 이동 중 사용과 네트워크: 공고 탐색·저장·지원 기록, 허브(이력서 프로필), 소셜, 에이전트, 내 활동(캘린더 포함), 요금제·사용량. 공고 추가 화면은 없고, 에이전트에 공고 링크나 본문을 붙여넣으면 내 공고가 된다 |
| fo-web | **fo-mobile의 웹 버전**. 개인은 에이전트만 뺀 모바일과 같은 Push를 쓴다(일반 채용공고 사이트처럼 탐색·북마크·지원, 공고는 로그인 없이도 본다). 기업은 사업자 확인 후 공고·지원자를 관리하고 기업 AI(공고 생성·서류 검토·면접 준비)를 유료로 쓴다. 채용공고 상세와 허브 프로필 상세는 모바일 앱 WebView에도 그대로 띄운다. 웹 화면 디자인은 Claude Design에 "웹" 페이지로 나중에 만든다 |

## 2. 배경과 문제 정의

- 구직 활동이 이력서 도구, 스프레드시트, 메일, 캘린더, 메모 앱에 흩어져 있다.
- AI 문서 생성 도구가 근거 없는 경력이나 수치를 만들어 신뢰를 잃는다.
- 지원 진행 상황과 후속 행동(팔로업 메일, 면접 준비)을 함께 추적하는 도구가 없다.
- (v2) 공고는 대부분 휴대폰에서 발견하지만 Push는 데스크톱에서만 쓸 수 있었다. 같은 직군 사람들과 커리어 정보를 나눌 곳도 없었다.

## 3. 목표

- Career Vault에 모은 근거가 공고 분석, 문서, 프로젝트, 면접 답변까지 이어서 추적된다. (Career Vault와 면접은 추후)
- 근거 없는 경험, 수치, 기술을 AI가 생성하지 못한다.
- 사용자가 승인하지 않은 지원 제출은 일어나지 않는다.
- (v2) 모바일에서 공고를 찾아 저장하고, 에이전트로 이력서를 만들고, 지원을 기록하는 일을 끝까지 할 수 있다.
- (v2) 모바일 앱은 토스·당근·원티드 느낌의 Push 브랜드 UI에 iOS 26 글래스 컴포넌트(원형 버튼, 탭 바, 검색창, 입력창, 시트, 메뉴)를 최대한 쓴다. Android는 같은 브랜드 UI를 불투명하게 그린다.
- (v2) 에이전트 탭은 Claude Code처럼 AI가 일하는 과정(상태 줄, 도구·결과 줄, 할 일, diff, 승인 패널)을 그대로 보여준다.

## 4. 비목표

- 기업 채용 담당자용 ATS 관리 기능. 단, v2에서 기업의 공고 등록, 지원자 단계 변경과 알림, 허브 제안은 지원한다.
- 내장 터미널과 자체 PTY
- 법적 허가를 확인하지 않은 채용 사이트로 자동 제출
- (v2) 외부 채용 사이트를 크롤링해 공고 카탈로그를 만드는 일
- (v2) 사용자 화면의 WebView로 외부 사이트를 여는 일
- (v2) 다른 채용 플랫폼, 회사 채용 사이트와의 연동
- (v2) 허브 노출 우선순위를 요금제로 파는 일
- (v2) 개인 웹의 에이전트(와 에이전트로 들어가는 버튼)
- AI 대화 면접(AI가 지원자와 직접 대화)과 인성 면접. 기업 Ultra 기능이 될 예정이지만 추후다.
- (v2, 이번 범위 밖)
  - 오프라인 캐시
  - 모바일 앱 비로그인 열람(fo-web은 공고 목록·상세·공고 검색을 로그인 없이 연다)
  - 데스크톱 API client 리팩터링
  - EAS·스토어 빌드
  - 모바일에서 올린 파일(PDF · DOCX)과 외부 파일 편집. Push가 만든 서류(Push 서류)는 모바일에서 섹션별로 고칠 수 있다(7.10).
  - 모바일 역량 보완 프로젝트(CLI)
  - 댓글 좋아요

## 5. 대상 사용자

| 사용자 | 하는 일 |
|---|---|
| 개인 구직자 | 근거 수집, 공고 분석, 문서 생성, 지원, 면접, 오퍼 관리 |
| 재직자 (v2) | 허브에 프로필을 올리고 커리어 상태를 표시한다. 소셜에서 소통한다. |
| 기업 (v2, 회사 + 담당자, `is_employer`) | 사업자 확인을 거친 회사의 담당자가 공고를 올리고, 지원자를 관리하고, 허브 프로필에 제안을 보낸다. 기업 AI를 요금제로 쓴다. |

개인은 기업이 아닌 사용자 전체(구직자 + 재직자)다.

UI는 한국어와 영어를 지원하고, 번역 리소스에는 ja와 vi도 있다.

## 7. 기능 요구사항

`[공통]`은 데스크톱과 모바일 모두, `[D]`는 데스크톱만, `[M]`은 모바일만 해당한다. 화면 구조는 [feature-map.md](feature-map.md)에, 규칙은 [feature-spec.md](feature-spec.md)에 있다.

### 7.1 Career Vault [D] — 추후
- 기존 이력서, GitHub, 경력, 학력, 기술, 성과 수치, 프로젝트 증거를 한 번만 수집한다.
- AI가 만든 내용은 모두 원본 근거와 연결한다. 근거 없는 경험은 생성하지 못하게 막는다.
- 이력서 파일 업로드는 `[공통]`이다. 모바일에서는 마이 > 서류에서 올린다.

### 7.2 공고 [공통]
공고는 출처에 따라 둘로 나뉜다.

| 구분 | 출처 | 보관 | 노출 범위 |
|---|---|---|---|
| A. 내 공고 | 데스크톱 "+ 공고 추가"에서 사용자가 준 링크 하나를 서버가 읽는다. 텍스트를 붙여넣거나 데스크톱 DOM으로 가져와도 된다. 모바일은 에이전트에 링크나 본문을 붙여넣어 만든다. | 그 사용자의 `jobs` | 본인만 |
| B. 기업 공고 (v2) | 기업 회원이 fo-web(기업 로그인)에서 직접 올린다. | `job_postings` | 모든 사용자 |

- A를 읽을 때 지킬 것
  - 로그인, 유료 공고, CAPTCHA를 우회하지 않는다. 막히면 텍스트 붙여넣기로 받는다.
  - 사이트별로 속도를 제한한다.
  - 출처와 원문 링크를 표시한다.
- 요구 기술, 역할, 우대사항, 키워드, 위험 요소와 후보자 사이의 차이를 분석한다 `[D]`.
- 모바일에는 공고 추가 전용 화면이 없다(링크·텍스트 추가, 읽는 중·실패 화면 없음). 대신 에이전트에 공고 링크나 본문을 붙여넣으면 내 공고(A)를 만든다. 홈, 채용공고 페이지, 통합 검색에서 B를 검색하고 필터한다 `[M]`. 홈과 검색에서 A를 어떻게 보여줄지는 미결이다(16장).
- 모바일 공고 화면 `[M]`
  - 홈: 헤더("Push." · 검색 버튼 · 알림함 버튼), 3D 카드 3개(채용공고 · 북마크 · 내 활동), "새로 올라온 공고" · "마감 임박 공고" · "이번 주 많이 본 공고" 가로 스크롤 섹션과 각 섹션의 전체보기. "마감 임박"은 마감 7일 이내 공고다(푸시 알림의 마감 3일 전과 별개). 인사말, 적합도 카드, 필터 칩 줄은 없다.
  - 채용공고 페이지: "공고 N개", 필터 칩(전체 · 직군 · 기술 스택 · 경력 · 지역 · 고용형태, 모두 여러 개 선택), 정렬(최신순), 2열 무한 그리드
    - 직군 8개: 개발 · 데이터 · 디자인 · 기획 · 마케팅 · 영업 · 인사 · 경영지원
    - 경력: 신입 · 1–3년 · 4–6년 · 7–9년 · 10년+
    - 고용형태: 정규직 · 계약직 · 인턴 · 프리랜서 · 파견
    - 지역: 1단계에 원격 포함, 2단계는 구별 공고 수 표시
  - 통합 검색: 최근 검색어(모두 지우기), 지금 많이 찾는 검색어 1–8위, 결과 탭(공고 · 사람 · 게시글, 관련도순)

### 7.3 지원 관리 [공통]
- 상태 기계는 `DISCOVERED → PREPARING → READY → APPLIED → SCREENING → INTERVIEW → OFFER → ACCEPTED | REJECTED | WITHDRAWN`이다.
- `APPLIED`는 제출(submission)을 거쳐야만 된다. 최종 제출은 지원 건마다 사용자가 승인한다.
- 지원 사이트 어댑터(Wanted, Jumpit, JobKorea)는 기본으로 꺼져 있고, 수동 체크리스트를 제공한다.
- 모바일에서는 기업 공고에 "지원하기"를 누르고 제출할 서류(AI로 맞춘 서류 / 원본, 포트폴리오 함께 첨부 가능)를 골라 지원을 기록한다. 마이 > 내 활동 > 지원활동에서 본다.

### 7.4 문서 작업실 [D]
- 이력서와 포트폴리오는 PDF로, 자기소개서는 DOCX로 출력한다. 템플릿은 심플, 모던, 크리에이티브, ATS 네 가지다(현재 코드는 CLASSIC, MODERN, COMPACT라서 바꿔야 한다). 프로필 사진은 템플릿과 상관없이 모든 템플릿에 넣을 수 있다.
- TipTap 선택 영역에서 AI 수정을 한다: 다시 쓰기, 줄이기, 수치 강조, 톤 변경, 공고 맞춤.
- 문서마다 공고 적합도, 근거 충실도, 가독성, ATS 점수를 보여준다. 근거가 없는 주장이 있으면 확정하지 못한다.

### 7.5 에이전트 [공통]
- 단계 게이트 워크플로(Phase 0–6)로 이력서를 만든다. 게이트마다 사용자 승인을 받는다.
- 토큰은 SSE로 스트리밍한다. 연결이 끊겨도 이어서 받을 수 있다.
- 모바일 "에이전트" 탭(예전 이름 "AI 채팅")은 같은 대화 목록을 쓴다. 이력서만이 아니라 공고 찾기, 지원 현황, 캘린더, 허브 프로필, 제안 답장, 글쓰기까지 Push 전체를 다룬다. 화면에는 페이즈 이름을 보여주지 않고 Claude Code 방식으로 진행을 보여준다([feature-spec.md](feature-spec.md) 15장).
- 첫 화면은 빠른 시작 12개로 시작한다. 탭 바는 대화 화면에서만 숨기고, 첫 화면·빠른 시작 시트·대화 목록에서는 보인다. 공고 상세의 "AI로 맞추기", 마이 › 서류의 "AI로 만들기"·"AI로 고치기"에서도 바로 들어온다. `@`로 북마크 공고, 마이 › 서류, 내 링크, 바로가기(자주 하는 일)를 언급할 수 있다.
- 실행 방식은 항상 묻기 · 자동(기본) · 바로 실행 3단계다. 입력창 칩과 계정 모달에서 바꾼다. 예전 "바꾸기 전에 확인" 스위치를 대신한다.
- 대화 화면 헤더 가운데에는 대화 제목 대신 마스코트 로고를 둔다. 대화는 고정 · 보관 · 삭제 · 공유할 수 있다. 보관한 대화는 대화 목록 맨 아래 "보관한 대화"에서 본다.
- 공고 상세에 들어가면 고른 서류를 기준으로 적합도를 자동으로 계산해("내 적합도 · {서류명}") 점수 링, 항목 막대 3개(기술 스택·경험 연관성·키워드), 부족한 점 한 줄, "조금만 고치면 N점대예요"로 보여준다. 홈 공고 카드에는 적합도를 표시하지 않는다. 적합도 상세는 요금제로 나눈다: FREE 점수만(항목별 점수와 약점은 흐리게 잠금), PRO 항목별 점수와 약점("이렇게 고치면 N점대"는 잠긴 한 줄), ULTRA "이렇게 고치면 N점대"까지(접힌 줄을 펼쳐 고칠 점 제안). 총점 카드는 처음 화면에 보인다. 웹 브라우저에서는 계산하지 않고 마이 › 내 활동에서만 점수를 보여준다.
- 슬라이드 바 메뉴는 새 대화 · 내 서류 · 내 링크 · 북마크한 공고다. 내 링크는 두 종류를 모은다: 공고 링크(에이전트에 붙여넣거나 쓴 링크)와 내 프로필 링크(GitHub·포트폴리오·블로그 등). 내 링크는 에이전트의 재료로 쓰고 `@`로 언급할 수 있다. 내 서류 · 내 링크 · 북마크한 공고는 계정 모달과 같은 모달로 열린다. GitHub 링크를 추가하면 AI가 README와 커밋을 읽어 둘 수 있다. 대화 목록은 상태 배지(확인 필요 / 작업 중)와 마지막 진행 줄을 보여주고 대화 검색을 지원한다.
- 모바일 계정 모달(에이전트 슬라이드 바에서 연다)에서 AI가 참고하는 내 정보, 대화 설정(답변 말투 · 실행 방식), 요금제를 다룬다.
- 에이전트를 쓰려면 참고 데이터 제공(7.16)에 동의해야 한다. 에이전트를 처음 열면 동의 시트가 뜨고, 동의하지 않으면 에이전트를 쓸 수 없다.

### 7.6 역량 보완 프로젝트 [D]
- 부족한 역량을 기준으로 프로젝트 블루프린트를 제안한다.
- 외부 Terminal에서 코딩 CLI(`CODEX | CLAUDE_CODE | GROK_BUILD`)를 승인을 받은 뒤 실행한다.
- 커밋, 테스트, 지표를 검증한 뒤에만 Career Vault에 반영한다.
- 역량 보완 프로젝트 개수는 요금제로 제한한다(7.13).

### 7.7 면접·캘린더·연동 [D, 캘린더는 공통]
- 면접 준비(예상 질문, STAR 답변, 회사 조사, 회고)는 **추후** 진행한다. 단, 모바일 지원한 공고 상세의 "AI로 면접 준비"는 이번 범위다. 누르면 그 공고로 면접을 준비하는 에이전트 대화가 열린다.
- 내부 캘린더와 Google Calendar를 연동한다. Gmail 동기화는 베타 플래그 뒤에 둔다.
- 캘린더는 `[공통]`이다. 모바일에서는 마이 > 내 활동 > 캘린더에서 본다(월 달력, 면접·마감·후속 연락·커피챗·직접 추가 색 점, 일정 추가, Google 캘린더 연결).

### 7.8 허브: 이력서 프로필 (v2) [M]
- 프로필 항목: 헤드라인, 직군, 연차, 커리어 상태(만족 / 이직·구직중 / 프로필 피드백), 소개, 경력 타임라인, 기술 스택, 팔로잉 · 팔로워 · 게시글 수, 제안 받기 여부, 대표 이력서
- 허브 자체 검색창("이름, 직무, 기술 검색". 통합 검색이 아니다), 직군 토글 칩(개발·디자인·기획·마케팅·데이터·영업), 재직 기간(0–2·3–5·6–9·10+년)·커리어 상태 필터를 제공한다. 필터는 바텀 시트이고, 필터 버튼(슬라이더 아이콘)에 적용한 개수를 배지로 보여준다.
- 탐색 필터는 두 가지다: 추천(내 직군과 같음), 제안(내가 제안을 보낸 프로필, "보낸 제안 N").
- 팔로우와 제안하기. 제안은 프로필마다 한 번만 보낼 수 있고 메시지는 500자까지다.
- 받은 제안은 상대의 **알림함**(푸시 포함)과 **마이 헤더 제안함**으로 전달된다.
- 제안을 수락하면 두 사람이 1:1 메시지로 대화를 시작한다. 수락한 제안에서 서로 메시지를 주고받는다.

### 7.9 소셜 (v2) [M]
- 카테고리: 전체, 직장 생활, 개발, 일상, 커리어, 소통, 커피챗, 마케팅·광고
- 게시물은 무한 스크롤로 보여준다. 이미지는 최대 4장이고 댓글과 답글을 달 수 있다. 조회수는 게시물 상세에서만 보여준다(목록 카드에는 없다).

### 7.10 마이 (v2) [M]
- 상단 탭: 프로필 | 서류(Push 서류 · 올린 파일) | 내 활동(지원활동·캘린더·북마크·팔로우·게시글)
- 프로필은 허브 프로필과 같은 화면이다(헤더 통계 "N 팔로잉 · N 팔로워 · N 게시글"). 전체 편집 버튼은 없고 섹션(기본 정보·소개·경력·기술 스택)마다 편집 버튼이 있다.
- 서류: "Push 서류"(Push와 AI가 만든 공고별 서류와 적합도. 모바일에서 섹션별로 고치고 "AI로 고치기" · "이 공고에 지원")와 "올린 파일"(PDF · DOCX 20MB까지. 모바일에서 고칠 수 없고 AI만 고친다). 올린 파일 보기(미리보기, 공유, "AI로 고치기", "내 프로필로 전환"(기본 정보·소개·경력·기술 스택 중 반영할 항목 선택)), 서류 가져오기(파일에서 고르기 / AI로 새로 만들기)
- 지원활동 배지: 지원함 · 서류 · 면접 · 합격 · 불합격. 지원한 공고 상세는 읽기 전용이고 "AI로 면접 준비"만 있다.
- 내 활동 › 팔로우와 게시글은 탭 없이 위아래 섹션으로 보여준다(팔로잉 / 팔로워, 내가 쓴 글 / 댓글 단 글).

- 마이 헤더 오른쪽 위: 제안함(안 읽은 수 배지)과 설정(톱니바퀴) 글래스 버튼. 세 탭 모두 같다.
- 제안함: 받은 제안 / 보낸 제안. 받은 제안 상태는 새 제안·수락함·거절함, 보낸 제안 상태는 읽지 않음 → 읽음 → 수락함 / 거절함이다. 상세에서 거절 또는 수락하고 답장하기. 수락하면 1:1 메시지로 이어진다. 제안에 공고를 함께 보낼 수 있다.
- 설정: 계정, 알림(마감 임박·제안·댓글과 답글·AI 작업 완료·지원 상태 변경), 허브 공개(프로필·커리어 상태·연락처), 일반 › 언어(한국어 / English), 에이전트(기본 말투·내 자료 읽기 허용·참고 데이터 제공), 고객센터·약관·로그아웃

### 7.11 푸시 알림 (v2) [M]
- Push 앱의 푸시 알림을 전체 구현한다. iOS(APNs)와 Android(FCM)를 `expo-notifications`로 받는다.
- 알림 종류는 설정의 스위치 5개와 같다: 마감 임박 공고(북마크 공고 마감 3일 전), 제안 받음, 댓글과 답글, AI 작업 완료(앱을 닫아도 알림), 지원 상태 변경(기업이 내 지원의 단계를 바꿨을 때).
- 같은 알림이 앱 안 **알림함**(홈 헤더 글래스 버튼)에도 쌓인다.
- 알림을 누르면 해당 화면으로 바로 간다(공고 상세, 제안 상세, 게시물 상세, 에이전트 대화, 마이 › 내 활동 › 지원활동).
- 설정에서 종류별로 끌 수 있다. 처음 실행 시 OS 알림 권한을 요청한다.

### 7.12 승인 체계 [공통]
- 승인 종류: `EVIDENCE_USE`, `DOCUMENT_FINALIZE`, `APPLICATION_SUBMIT`, `CLI_EXECUTE`
- 승인은 기본 24시간 동안 유효하고, 대상 revision이 바뀌면 무효가 된다(`APPROVAL_STALE`).

### 7.13 결제 [D, 요금제·사용량은 공통]
요금제는 개인과 기업 두 갈래다. 따로 결제하고 따로 관리한다. 모두 월 구독이고 통화는 USD다. 연간 요금제는 없다.

| 등급 | 개인 | 기업 |
|---|---|---|
| 하위 | FREE · 무료 · DeepSeek 최신 | Basic · $20 · Sonnet 최신 |
| 중간 | PRO · $30 · Sonnet 최신 | Pro · $100 · Opus 최신 |
| 상위 | ULTRA · $100 · Opus 최신 | Ultra · $200 · Fable 최신 |

- 요금제는 Push AI 사용에만 적용한다. 서류 내보내기와 대화 기록 보관은 모든 요금제에 열려 있다(대화 기록은 사용자가 지울 때까지 보관). 예외: 기업 담당자 초대 수(Pro 2명, Ultra 5명).
- 기업 요금제는 같은 등급의 개인 요금제보다 한 단계 위 모델과 레버를 쓴다. 그래서 같은 등급의 개인 AI가 다듬은 서류를 기업 AI가 걸러낼 수 있다.
- 화면과 데이터에는 모델명 대신 요금제명을 쓴다. 요금제 화면의 카드에는 가격과 사용량 문구만 보여주고 모델명은 적지 않는다(헤드라인 "요금제마다 쓸 수 있는 양이 달라요").
- 화면에는 크레딧 수치를 보여주지 않고, "크레딧"이라는 말은 추가 구매 이름 "크레딧 구매"에만 쓴다(개인·기업 모두). 사용량은 문구와 퍼센트로만 보여준다. 크레딧은 서버 안에서만 쓰는 계량 단위다.
- 요금제 차이를 만드는 레버(시작값, 운영하며 조절):

  | 레버 | FREE | PRO | ULTRA | 기업 Basic | 기업 Pro | 기업 Ultra |
  |---|---|---|---|---|---|---|
  | 월 크레딧(내부 계량 단위, 화면에 보여주지 않는다) | 300 | 5,000 | 20,000 | 3,000 | 15,000 | 30,000 |
  | 추론 강도 | `LOW` | `MEDIUM` | `HIGH` | `MEDIUM` | `HIGH` | `MAX` |
  | 작성 방법 · 레퍼런스 | 기본 | 확장 | 전체 | 확장 | 전체 | 전체 |
  | 참고 연차 범위 | 같은 연차 | ±1년 | ±2년 | ±1년 | ±2년 | 전 연차 |
  | 참고 점수 구간 | 같은 점수대 | 한 단계 위까지 | 최상위까지 | 한 단계 위까지 | 최상위까지 | 전 구간 |

- 추론 강도는 요금제가 정한다. 사용자가 고르지 않는다.
- 역량 보완 프로젝트(동시에 가진 개수): FREE 5개 · PRO 20개 · ULTRA 사용량 한도 안에서 무제한
- 사용량은 매월 1일 다시 채워진다. 더 쓰려면 요금제 화면의 "크레딧 구매"를 쓴다. 다 쓰면 "요금제 올리기"와 "크레딧 구매"를 함께 보여준다. 이미 ULTRA면 "크레딧 구매"만 보여준다(기업도 추가 구매할 수 있다).
- 개인은 앱 인앱 결제(App Store · Google Play)로만 결제한다. 가격은 Stripe와 같다. 구독은 서버에서 하나로 합친다. 웹과 데스크톱에서는 개인 요금제를 결제하지 않는다.
- 기업은 fo-web에서만 Stripe Checkout(카드)으로 결제한다. 요금제·사용량은 회사 단위다.
- 이번 달 사용량을 퍼센트로 조회한다.
- 상세 규칙은 [feature-spec.md](feature-spec.md) 9장에 있다.

### 7.14 fo-web 개인 웹 (v2)
- 모바일 화면 구조를 웹으로 옮기고 **에이전트만 뺀다**. 에이전트로 들어가는 버튼(AI로 맞추기, AI로 고치기·만들기)과 에이전트로 내 공고 추가도 없다.
- 일반 채용공고 사이트처럼 쓴다: 탐색 · 검색 · 필터, 북마크, 공유, 지원하기, 지원 기록 확인. 앱에서 네이티브가 그리는 북마크 · 공유 · 지원하기 버튼을 웹에서는 페이지가 직접 그린다.
- 로그인 없이 공고 목록 · 공고 상세 · 통합 검색의 공고 탭을 본다. 허브와 소셜은 로그인해야 본다. 북마크 · 지원하기를 누르면 로그인 후 원래 공고로 돌아온다.
- 적합도는 웹에서 계산하지 않는다. 마이 › 내 활동에서만 앱에서 계산한 점수를 보여준다. 공고 상세와 목록에는 없다.
- 서류 가져오기는 파일 업로드만 있다. 개인 요금제 결제는 없다.
- 상세 규칙은 [feature-spec.md](feature-spec.md) 16장에 있다.

### 7.15 fo-web 기업 웹과 기업 AI (v2)
- 개인 계정과 기업 계정은 따로다. 기업 계정은 Google 또는 이메일로 가입하고, 기업 이메일은 계정 하나에만 쓴다. 개인 계정은 이메일 없이 휴대폰 번호로 구분한다.
- 사업자 확인(국세청 진위확인 · 상태조회 API)을 통과해야 공고 등록과 기업 AI를 쓴다.
- 회사 단위로 결제하고 담당자를 여러 명 둔다(관리자 1명 + 초대한 담당자). 공고 · 지원자 · 요금제 · 사용량 · 기업 AI 대화는 회사에 속한다.
- 화면은 개인 웹과 같다. 차이: 공고 상세의 "이 공고 참고해서 만들기"(지원하기 대신), 허브 프로필 없음, 소셜은 회사명 + 기업 배지, 기업용 마이(회사 정보 · 담당자 관리 · 기업 요금제), 내 공고 관리, 지원자 목록과 서류.
- 지원자 관리: 지원 단계(서류 통과 · 면접 · 합격 · 불합격)를 바꾸면 지원자 기록이 같이 바뀌고 지원자에게 알림이 간다.
- 기업 AI는 기업 에이전트 안에서 대화로 동작한다.

  | 기능 | Basic | Pro | Ultra |
  |---|:-:|:-:|:-:|
  | AI 공고 생성 | ✓ | ✓ | ✓ |
  | AI 서류 검토 (Push 지원자) | ✓ | ✓ | ✓ |
  | AI 면접 준비 (질문 목록 · 검증 포인트) | – | ✓ | ✓ |

- 기업 AI는 의견만 낸다. 합격 · 불합격은 담당자가 정한다.
- 상세 규칙은 [feature-spec.md](feature-spec.md) 17장에 있다.

### 7.16 참고 데이터 (v2)
- AI는 다른 사용자가 이미 평가 받은 결과(공고맞춤 점수 · 연차 · 서류)를 기준선으로 쓴다. 개인 AI는 작성 레퍼런스로, 기업 AI는 과장 판별 기준으로 쓴다.
- 원문은 저장하지 않고 가공 결과(메타데이터 · 서류 특징 · 일반화한 문장 구조)만 저장한다.
- 에이전트를 쓰려면 동의가 필요하다. 개인은 에이전트를 처음 열 때 동의 시트에서 동의하고, 마이 › 설정 › 에이전트 › 참고 데이터 제공 스위치로 언제든 끈다. 끄면 에이전트를 쓸 수 없고 그 사람의 가공 데이터를 지운다. 에이전트 밖의 기능(공고, 허브, 소셜, 마이)은 동의 없이 쓴다. 다른 사람의 문장은 답변과 화면에 나오지 않는다.
- 데이터가 적은 구간(구간당 30개 미만)은 참고하지 않는다. 참고 데이터가 없어도 모든 AI 기능은 동작한다.
- 상세 규칙은 [feature-spec.md](feature-spec.md) 18장에 있다.

- 빈 상태에는 다음 행동 버튼을 하나 둔다(예: 필터 초기화, 새 대화 시작). 지우는 동작(서류, 경력, 내 링크)은 확인 창을 띄우고, 지운 뒤에는 "되돌리기" 토스트를 보여준다. 화면별 문구는 [feature-spec.md](feature-spec.md)에 있다.

## 11. 비기능 요구사항

- 보안: 키, 이력서, 메일 내용, 토큰을 로그나 분석 이벤트에 남기지 않는다. 다른 사용자의 리소스는 404로 숨긴다.
- 서버가 외부 원문을 읽을 때는 SSRF 검증 프록시를 거친다. 원문은 신뢰하지 않는 데이터로 다루고 AI 도구 실행 지시로 쓰지 않는다.
- 성능
  - 모바일 홈 검색 p95 500ms 이하. 외부 호출 없이 DB만 조회한다.
  - 채팅 첫 토큰 p95 3초 이하
- 가용성: 클라이언트가 끊겨도 채팅 작업은 서버 큐에서 계속 진행되고, 다시 연결하면 이어서 받는다.
- 접근성
  - 데스크톱: 키보드 탐색, VoiceOver 레이블, 창을 줄였을 때의 레이아웃, 다크 모드
  - 모바일: VoiceOver·TalkBack 레이블, Dynamic Type, "투명도 줄이기"

  - 공고 카드: 박스 없이 큰 대표 사진, 사진 오른쪽 아래 북마크 버튼, 회사, 제목 한 줄(말줄임), 지역·경력. D-day와 적합도 배지는 없다.
  - 홈에는 필터 칩 줄이 없다. 채용공고 페이지의 필터는 iOS·Android 모두 bottom sheet다.
- **허브**
  - 검색, 직군 토글 칩(iOS는 SwiftUI glass 버튼, Android는 `FilterChip`)
  - 재직 기간, 커리어 상태, 탐색 필터는 바텀 시트에 넣는다. 필터 버튼은 슬라이더 아이콘과 적용 개수 배지이고, 시트 아래는 "프로필 N개 보기"다.
  - 프로필 상세(WebView) 툴바에 "제안하기"를 둔다. 누르면 메시지 입력 formSheet가 열리고 `POST /profiles/{id}/offer`를 호출한다.
- **소셜**
  - 카테고리 칩을 둔다.
  - 목록은 `useInfiniteQuery`와 `FlatList onEndReached`로 무한 스크롤한다.
  - 툴바의 작성 버튼을 누르면 compose로 이동한다.
  - compose
    - 입력창은 iOS에서 SwiftUI `TextField`, Android에서 Compose `TextField`를 쓴다.
    - 이미지는 `expo-image-picker`로 고르고 업로드한다.
  - `(social)/posts/[id].tsx`: RN 상세 화면
    - 본문, 이미지(`expo-image`), 댓글 목록을 보여준다.
    - 댓글 입력창은 하단에 고정한 glass TextField다. 채팅 composer를 재사용한다.
- **에이전트** (탭 이름. 라우트 그룹은 `(chat)`, 대화 화면은 `chat/[id].tsx`)
  - Claude Code 방식 진행 표시와 모션 스펙은 [feature-spec.md](feature-spec.md) 15장을 따른다.
  - 기존 `conversations` API를 쓴다. `expo/fetch`로 스트림을 읽고 `parseFrames`로 해석한다.
  - 플랫폼별로 나누는 건 입력창뿐이다: `chat-composer.ios`(glassEffect TextField), `chat-composer.android`
- **마이**
  - 세그먼트: iOS는 SwiftUI `Picker` segmented, Android는 segmented button
  - 프로필
  - 서류: `expo-document-picker`로 고른 파일을 `POST /sources`로 올리고 `PUT /me/profile`을 호출한다.
  - 내 활동: 지원활동, 캘린더, 북마크, 팔로우, 게시글

## 14. 가정과 리스크

- 서버가 공고 URL을 읽으려 할 때 봇 차단에 걸릴 수 있다. 막히면 텍스트 붙여넣기로 받는다.
- 기업 공고(B)가 처음에는 거의 없다. 모바일에는 공고 추가 화면이 없고 에이전트로 만든 내 공고(A)는 홈에 나오지 않으므로 홈이 비어 보일 수 있다. 내 공고(A)를 어떻게 보여줄지는 16장에 남긴다.
- 이미지는 로컬에서는 디스크에 저장하고, 배포할 때 R2로 바꾼다. DB에는 key만 저장한다.
- core-api와 gateway는 Neon HTTP 드라이버를 쓴다. 로컬 Postgres에 붙이려면 Neon HTTP 프록시가 필요하다.
- `@expo/ui` Android 컴포넌트 이름과 SwiftUI glass 모디파이어 이름은 구현을 시작할 때 `.d.ts`에서 확인한다.
- 참고 데이터는 다른 사용자 서류를 가공해 쓴다. 에이전트 사용 조건으로 받는 별도 동의, 철회 시 삭제, 원문 비노출을 지킨다. 동의를 에이전트 사용 조건으로 묶어도 되는지도 출시 전 검토에 넣는다. 출시 전 개인정보 전문가 검토가 필요하다.
- 해외 AI 제공사로 서류를 보낸다(국외 이전 고지). DeepSeek는 OpenRouter 제공사 라우팅으로 미국 호스팅만 쓴다.
- 출시 직후 참고 데이터가 적어 기업 서류 검토가 기준선 없이 동작한다.

## 15. 개발 원칙

- `develop` 브랜치를 기준으로 한다. 브랜치 이름은 `feat|fix|refactor|chore|docs|test/<short-kebab>`이고, 커밋은 scoped Conventional Commit, 병합은 squash merge로 한다.
- 릴리스는 develop을 main으로 올리는 PR(merge commit)로 한다. push-be는 main에 push하면 배포된다. 마이그레이션은 수동으로 실행한다.
- v2 작업은 `feat/recruiting` 브랜치에서 하고, 승인하기 전에는 develop에 병합하지 않는다.
- 세 저장소(push-workspace, push-fe, push-be)는 서브모듈로 연결하고 커밋을 고정해서 관리한다.

## 16. 미결 사항

- 백엔드 v2 설계 전체(API 경로, 테이블, 담당 Worker). [api-spec.md](api-spec.md) 4–5장은 초안이다.
- 공고별 적합도를 어디서 계산할지(백엔드 미확정). 계산 시점은 공고 상세에 들어갈 때로 정했다.
- "이번 주 많이 본 공고"에 필요한 조회수 집계
- 로컬에서 쓸 Neon HTTP 프록시 이미지
- fo-web의 운영 도메인과 CORS 허용 목록. 지금은 `tauri://localhost`와 localhost만 허용한다.
- 설정의 에이전트 항목(기본 말투, 내 자료 읽기 허용)과 계정 모달의 대화 설정이 겹친다. 어디에 둘지 정해야 한다.
- 데스크톱 "+ 공고 추가"(내 공고)를 유지할지, 홈과 검색에서 내 공고를 어떻게 다룰지
- "마감 임박 공고" 섹션의 기준(전체 공고 / 북마크 공고)
- 요금제 크레딧(내부 계량 단위, 월 300 / 5,000 / 20,000)을 기존 마이크로크레딧 단위와 맞추는 일
- 에이전트 흐름의 기준: 단계별(Phase) 보드 흐름(진행 방식 → 전략 → 템플릿 → 품질 검사 게이트)과 최신 보드 흐름(할 일 5개를 바로 진행하고 승인은 diff 1회) 중 무엇을 따를지
- 구버전 프로토타입과 모션 보드 정리
- 휴대폰 번호 인증 문자 발송 업체
- 개인 회원의 회사 인증 화면 위치와 구성
