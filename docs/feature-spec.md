# Push 기능 명세

- 버전: 2.0
- 작성일: 2026-10-20
- 상태: 초안
- 관련 문서: [PRD.md](PRD.md), [feature-map.md](feature-map.md), [api-spec.md](api-spec.md)

`[공통]`은 데스크톱과 모바일 모두, `[D]`는 데스크톱만, `[M]`은 모바일만 해당한다. 상태 값과 오류 코드는 [api-spec.md](api-spec.md)를 따른다.

## 0. 공통 원칙

- 화면에는 실제 저장된 데이터만 보여준다. 샘플 회사나 성과를 사용자의 사실처럼 저장하거나 표시하지 않는다.
- 연결되지 않은 외부 기능은 "미설정" 상태와 다음에 할 행동을 보여준다(`NOT_CONFIGURED`, `INTEGRATION_REQUIRED`). 성공한 것처럼 보이게 하지 않는다.
- 오류는 원인과 다음 행동을 한 문장으로 알려준다. 예: "공고를 읽지 못했어요. 본문을 붙여넣어 주세요."
- 수정이 겹쳐서 `REVISION_CONFLICT`가 나면 자동으로 덮어쓰지 않는다. 최신 상태를 다시 불러오고 사용자가 고르게 한다.
- 생성 요청(POST)은 클라이언트가 `Idempotency-Key`를 만들어 보낸다. 다시 시도할 때도 같은 키를 쓴다.
- 시간이 걸리는 작업은 Operation(202)으로 받는다. 진행 상태를 보여주고 취소할 수 있게 한다.

### 0.1 한글 검색 규칙 [M, fo-web]
모든 검색과 목록 거르기에 토스의 `es-hangul`을 쓴다. 대상은 통합 검색, 채용공고 기술 스택 검색, 허브·소셜 검색, `@` 언급 거르기, 대화 검색, 내 링크·내 서류 목록이다.

| 입력 | 예시 | 쓰는 함수 |
|---|---|---|
| 초성 검색 | "ㅁㅇㅍㅇ" → 모아페이, "ㅂㅇㄷ" → 백엔드 | `getChoseong` |
| 입력 중인 글자 | "백ㅇ", "모앞" → 백엔드, 모아페이 (자모 단위로 앞부분이 맞으면 찾는다) | `disassemble` |
| 한/영 전환을 잊은 입력 | "ahdkvpdl" → 모아페이 | `convertQwertyToHangul` |
| 일반 입력 | "결제" → 결제 승인 API | 부분 일치 |

- 강조: 맞은 부분을 글자 단위로 강조한다. 초성으로 맞으면 해당 글자 전체를 강조한다.
- 순서: 정확히 맞음 → 앞부분이 맞음 → 초성이 맞음 → 영타를 바꿔서 맞음 순으로 위에 둔다.
- 앱 안에 이미 있는 목록(`@` 언급, 내 링크, 내 서류, 대화, 기술 스택 추천)은 기기에서 바로 거른다. 서버 검색(공고 · 사람 · 게시글)은 같은 규칙으로 서버가 찾는다.

## 1. 인증 [공통]

- Google과 GitHub OAuth를 PKCE(S256)로 처리한다. 콜백 주소는 `push://auth/callback`이다. 로컬 웹은 `http://localhost:5173/auth/callback`을 쓴다.
- 데스크톱은 Tauri 딥링크로 돌아온다. 모바일은 `expo-web-browser`의 `openAuthSessionAsync`로 돌아온다.
- access token은 15분, refresh token은 30일 유효하다. 401을 받으면 refresh를 한 번만 시도한다(single-flight). refresh token은 쓸 때마다 새로 바뀐다.
- 토큰 저장 위치: 데스크톱은 `push-session`(localStorage), 모바일은 `expo-secure-store`
- 개발 빌드에서는 `DEV_AUTH_TOKEN`으로 로그인할 수 있다. 운영 환경에서는 허용하지 않는다.

## 2. AI 채팅 [공통]

- 대화는 제목, 고정 여부, 연결된 지원 건(선택)을 가진다. 보관한 대화는 목록에서 빠진다.
- 메시지를 보내면 `POST /conversations/{id}/messages`가 202를 돌려주고 서버 큐에서 실행된다. 앱을 닫아도 작업은 계속된다.
- 스트림 프레임은 `token`, `status`, `error`, `done`이다. 끊기면 `GET .../stream/active`에 `after` 또는 `Last-Event-ID`를 붙여 이어서 받는다.
- 단계 게이트(Phase 0–6)에서는 승인 카드를 보여주고 `POST /approvals/{id}/decision`을 호출한다.
- 입력 옵션
  - 실행 권한(`SUGGEST | CONFIRM_ACTIONS`)
  - AI 모델(provider·model)
  - 작업 강도(`LOW…MAX`)
  - BYOK 키 헤더
- 관리형 크레딧이 모자라면 `FEATURE_DISABLED`, BYOK 키가 없으면 `INTEGRATION_REQUIRED`를 보여준다.
- 모바일은 `expo/fetch`로 스트림을 읽는다. 입력창만 플랫폼별로 나눈다(`chat-composer.{ios,android}.tsx`). 모바일 화면 규칙은 15장에 있다.

## 3. 공고

### 3.1 내 공고 추가 [D]

모바일에는 공고 추가 전용 화면이 없다. 대신 AI 채팅에 공고 링크나 본문을 붙여넣으면 아래 규칙(URL·TEXT)으로 내 공고를 만들고, 그 링크는 내 링크(15.6)에 쌓인다. 기업 공고는 기업 회원이 fo-web(기업 로그인)에서 올린다.
- 추가 방식
  - 링크(`URL`): 서버가 그 URL 하나만 읽는다(httpx, 본문이 짧으면 Playwright).
  - 텍스트(`TEXT`)
  - 데스크톱 내장 브라우저 DOM(`DOM`) `[D]`
- 서버가 읽을 때 지킬 것
  - 로그인, 유료 공고, CAPTCHA를 우회하지 않는다.
  - 실패하면 텍스트 붙여넣기 화면으로 넘긴다.
  - 같은 사이트에 대한 요청은 속도를 제한한다.
  - SSRF 검증 프록시를 거친다.
- 결과는 본인의 `jobs` 행으로만 저장한다. URL은 자격증명이 없는 http(s)만 받는다.
- 필드 제한: company 1–200자, title 1–300자, sourceText 1–200,000자, deadline은 `YYYY-MM-DD`

### 3.2 공고 분석 [D]
- 근거(evidence)를 고르고 분석을 실행한다(`JOB_ANALYSIS`).
- 결과는 갭 분석이다: 충족, 부족, 우대 미충족, 위험, 적합도. 공고가 바뀌면 이전 분석에 `stale` 표시를 한다.

### 3.3 공고 검색 [M]
- 모바일은 기업 공고를 검색한다. AI 채팅으로 만든 내 공고를 홈과 검색에서 어떻게 보여줄지는 미결이다([PRD.md](PRD.md) 16장).
- 검색어는 제목과 회사에서 부분 일치로 찾는다(`pg_trgm`).
- 마감된 기업 공고(`closed_at`)는 숨긴다.
- 공고 카드: 박스 없이 큰 사진(공고 대표 이미지), 사진 오른쪽 아래 북마크 버튼, 회사, 제목 한 줄(넘치면 말줄임), 지역·경력. D-day와 적합도 배지는 없다.

#### 홈 (위에서 아래로)
- 헤더: 로고 "Push.", 오른쪽 위 **검색** 버튼(통합 검색으로 이동)과 **알림함** 버튼(종 모양, 안 읽음 배지). 본문에 검색창, 인사말, 적합도 카드, 필터 칩 줄은 없다.
- 3D 카드 3개(높이 100px)
  - 채용공고 → 채용공고 페이지
  - 북마크 → 마이 › 내 활동 › 북마크
  - 내 활동 → 마이 › 내 활동 › 지원활동
- 섹션: "새로 올라온 공고" · "마감 임박 공고"(마감 7일 이내. 푸시 알림의 마감 3일 전과 별개) · "이번 주 많이 본 공고". 카드는 가로로 스크롤한다. 섹션마다 전체보기가 있고, 채용공고 목록 프레임(2열 그리드)을 다시 쓴다.
- 스크롤하면 iOS 탭 바가 작은 글래스 원으로 줄어든다.

#### 채용공고 페이지
- 헤더: 뒤로, 제목, 검색
- 필터 칩: 전체 · 직군 · 기술 스택 · 경력 · 지역 · 고용형태. 칩을 누르면 바텀 시트가 열린다(iOS·Android 같음). 모든 필터는 여러 개 선택이다. 고른 칩은 "개발 외 1"처럼 첫 값과 나머지 개수로 보여준다. 시트 아래 버튼은 "공고 N개 보기"이고 고를 때마다 개수가 바로 바뀐다.
  - 직군: 개발 · 데이터 · 디자인 · 기획 · 마케팅 · 영업 · 인사 · 경영지원 (8개. 허브 직군 칩 6개와 다르다)
  - 기술 스택: 기술 검색, 선택한 기술, 내 프로필 기술, 많이 찾는 기술
  - 경력: 신입 · 1–3년 · 4–6년 · 7–9년 · 10년+
  - 지역: 시·도 → 구 2단계. 1단계에 원격이 있고, 2단계는 구마다 공고 수를 보여준다
  - 고용형태: 정규직 · 계약직 · 인턴 · 프리랜서 · 파견
- 전체 개수 "공고 N개"와 정렬(최신순). 커서로 페이지를 넘기는 2열 무한 그리드다.

#### 통합 검색
- 홈 헤더 검색 버튼에서 연다. 허브와 소셜도 같은 화면을 쓴다.
- 검색 전: 최근 검색어("모두 지우기"), "지금 많이 찾는 검색어" 1–8위
- 결과: 탭 공고 · 사람 · 게시글, 관련도순. 검색어와 맞는 부분을 강조한다. 초성·자모·영타 입력 규칙은 0.1을 따른다.

### 3.4 채용공고 상세 [공통]
- 데스크톱은 `/jobs/:id` 화면이다. 모바일은 fo-web `/postings/:id`를 WebView로 연다.
- 본문(fo-web): 회사 로고·회사명·업종 태그(예: 핀테크), 제목, D-day, 지역·경력·고용형태, **적합도**, 하는 일, 자격 요건, 우대 사항, 근무 조건, "원문 보기 · {회사} 채용 사이트" 링크(시스템 브라우저로 연다)
- 적합도: 상세에 들어가면 고른 서류를 기준으로 자동으로 계산한다(제목 "내 적합도 · {서류명}"). 계산하는 동안 "공고와 서류를 비교하는 중…"을 보여주고, 끝나면 점수 링, 항목 막대 3개(기술 스택 · 경험 연관성 · 키워드), "!" 표시와 부족한 점 한 줄, "조금만 고치면 N점대예요"를 보여준다.
- 모바일 툴바: 오른쪽 위에 북마크와 공유를 묶은 글래스 캡슐 버튼. 북마크는 기업 공고만 있다.
- 모바일 하단 버튼 2개
  - **AI로 맞추기**: 이 공고를 첨부한 채로 AI 채팅을 연다.
  - **지원하기**: 제출할 서류를 고르는 시트가 열린다. 서류에는 "AI로 맞춘 서류" / "원본" 라벨을 붙이고, 포트폴리오를 함께 고를 수 있다("함께 보낼 수 있어요"). 고르고 나면 기업 공고는 `apply`(`documentIds[]`)를 호출하고, 내 공고는 application을 만든다. 지원하면 버튼이 "지원 완료"(비활성)로 바뀌고 토스트 "지원했어요. 내 활동에서 진행 상황을 볼 수 있어요"를 띄운다.
  - Android 하단 툴바는 아이콘만 보이므로 아이콘과 접근성 라벨을 함께 단다.

## 4. 지원 관리 [공통]

- 단계: `DISCOVERED → PREPARING → READY → APPLIED → SCREENING → INTERVIEW → OFFER → ACCEPTED | REJECTED | WITHDRAWN`. ACCEPTED, REJECTED, WITHDRAWN은 끝 단계다.
- `APPLIED`는 제출(submission)로만 들어갈 수 있다. 직접 바꾸려 하면 `INVALID_TRANSITION`이 난다.
- 제출 흐름 `[D]`
  1. 제출 초안을 만든다. 확정된 문서 버전이 1개 이상 있어야 한다.
  2. `APPLICATION_SUBMIT` 승인을 받는다.
  3. 제출을 기록한다.
- 승인이 없거나 거부됐거나 다른 지원 건의 승인이면 제출하지 못한다.
- 이미 지원한 건은 `POST /applications/import`로 가져온다. 이때 `confirmed: true`가 필요하다.
- 채용 사이트 어댑터(WANTED, JUMPIT, JOBKOREA)는 기본으로 꺼져 있고 수동 체크리스트를 보여준다.
- 모바일은 마이 > 내 활동 > 지원활동에서 목록과 단계 배지를 본다(읽기 전용).

## 5. Career Vault와 파일 [D, 파일 등록은 공통]

> Career Vault는 **추후** 진행한다. 이력서 파일 등록(`/sources`)은 Vault와 별개라 이번 범위에 포함한다.


- 근거 종류: RESUME, GITHUB, CAREER, EDUCATION, SKILL, PROJECT
- 검증 상태: USER_PROVIDED, PENDING, VERIFIED, REJECTED
- 파일 업로드(`POST /sources`)
  - 형식: PDF, DOCX, TXT, MD
  - 크기: 20MiB 이하
  - 근거가 참조 중인 파일은 삭제할 수 없다(409).
- 가져오기(`EVIDENCE_IMPORT`): TEXT, MARKDOWN, PDF, DOCX, GITHUB. GITHUB은 연동이 필요하다.
- 모바일 마이 > 서류
  1. `expo-document-picker`로 파일을 고른다.
  2. `POST /sources`로 올린다.
  3. `PUT /me/profile {resumeSourceId}`로 대표 이력서를 지정한다.

## 6. 문서 작업실 [D]

- 종류: RESUME, PORTFOLIO, COVER_LETTER
- 템플릿: 심플, 모던, 크리에이티브, ATS (4종). 프로필 사진은 템플릿과 상관없이 모든 템플릿에 넣을 수 있다(마이 › 프로필 사진 사용). 현재 코드는 CLASSIC, MODERN, COMPACT라서 바꿔야 한다.
- 상태: DRAFT → FINALIZED, 또는 ARCHIVED
- 버전 관리
  - 버전마다 블록과 근거 참조(evidenceRefs)를 저장한다.
  - AI 생성(`DOCUMENT_GENERATE`), 선택 영역 수정(`DOCUMENT_REVISE`: REWRITE, SHORTEN, EMPHASIZE_METRICS, CHANGE_TONE, TAILOR_TO_JOB) 결과는 사용자가 적용해야 반영된다.
- 검토: 블록마다 주장 상태(SUPPORTED, NEEDS_REVIEW, UNSUPPORTED)와 품질 점수를 보여준다.
- 확정: `DOCUMENT_FINALIZE` 승인이 필요하다. UNSUPPORTED 주장이 있으면 `UNSUPPORTED_CLAIM`으로 막는다.
- 출력: 확정된 버전만 PDF나 DOCX로 출력할 수 있다. 결과 검증 항목은 한글, 링크, ATS 텍스트다.

## 7. 역량 보완 프로젝트 [D]

1. 갭 분석에서 블루프린트를 제안받는다(`PROJECT_BLUEPRINTS`).
2. 블루프린트를 선택한다.
3. 실행을 준비한다: provider, 작업 디렉터리(절대 경로), 프롬프트
4. `CLI_EXECUTE` 승인을 받는다.
5. 외부 Terminal에서 실행한다.
6. 결과를 기록한다.
7. 증거를 제출한다: 커밋 URL, 테스트 명령과 출력, 지표
8. 검증(`PROJECT_VERIFY`)을 통과하면 Career Vault에 반영한다.

- 실행 상태: DRAFT → APPROVAL_REQUIRED → RUNNING → VERIFYING → VERIFIED | FAILED
- 기기가 재시작되면 실행을 다시 붙이거나(REATTACH) 실패로 처리한다(MARK_FAILED).

## 8. 면접·캘린더·Google [D, 캘린더는 공통]

- 면접 (**추후**)

## 10. 허브 [M, 상세는 fo-web]

  - 직군, 연차
  - 커리어 상태: `satisfied` 만족, `seeking` 이직/구직중, `feedback` 프로필 피드백 (배지로 표시)

  - **경력 타임라인**: 회사 · 직무, 기간, 한 줄 설명

  - 검색: 통합 검색 화면을 함께 쓴다(3.3).

  - 재직 기간: 0–2년 · 3–5년 · 6–9년 · 10년+
  - 커리어 상태: 만족 · 이직/구직중 · 프로필 피드백
  - 탐색: 추천(내 직군과 같음) · 제안(내가 제안을 보낸 프로필). 제안 옆에 "보낸 제안 N"을 표시한다.
  - 하단: 초기화, "프로필 N개 보기"
- 상세(WebView): 프로필 헤더, 소개, 경력 타임라인, 기술 스택
  - 툴바(`Stack.Toolbar` right): 팔로우, 공유, 제안하기. 자기 자신은 팔로우할 수 없다.
- 제안하기 시트(글래스 form sheet)
  - 받는 사람: "{이름} 님에게", 직군 · 연차 · 커리어 상태
  - 메시지 1–500자, 글자 수 카운터("83 / 500")
  - 안내 문구: "제안은 {이름} 님의 알림과 메시지함으로 전달돼요."
  - "제안 보내기" → `POST /profiles/{id}/offer`. 프로필마다 한 번만 보낼 수 있다.
  - 받는 쪽: 푸시 알림과 알림함(홈 헤더)으로 알리고, 마이 헤더 **제안함**에 쌓인다(12.2).

## 12. 마이 [M]

- 상단 글래스 세그먼트: 프로필 | 서류 | 내 활동
- 프로필: **허브 프로필과 같은 화면**이다. 남들이 허브에서 보는 내 프로필을 그대로 보여준다.
  - 배지 아래 "허브에 이렇게 보여요 · 팔로워 N"
  - 화면 전체를 한 번에 편집 모드로 바꾸는 "편집" 버튼은 없다. **섹션마다 편집 버튼**이 있고, 누르면 그 섹션만 편집 시트가 열린다.

    | 섹션 | 편집 항목 |
    |---|---|
    | 기본 정보 | "기본 정보 편집" 버튼. 이름, 프로필 사진, 헤드라인, 직군, 연차, 커리어 상태, 제안 받기 여부 |
    | 소개 | 소개 글. "AI로 다듬기" |
    | 경력 | 경력 항목 추가·수정·삭제(회사, 직무, 기간, 한 줄 설명). 항목을 펼쳐서 편집하고 순서를 바꾼다 |
    | 기술 스택 | 검색해서 기술 칩 추가, 삭제 |

  - 저장하면 그 섹션만 `PATCH /me/profile`로 보낸다.
  - 팔로우·제안하기 버튼은 없다.
- 서류: "내 서류 N개" 파일 목록(형식 배지, 파일명, 크기, 날짜)과 "파일 등록"(PDF, DOCX, 20MB까지)
  - 빈 상태: "아직 등록한 서류가 없어요" + **파일 등록**, **AI로 만들기**(AI 채팅 탭으로 이동)
  - 서류 가져오기 시트: 파일에서 고르기 / AI로 새로 만들기. 올리는 동안 "올리는 중 · x / yMB" 진행률을 보여주고, 끝나면 토스트 "이력서 파일을 올렸어요"를 띄운다.
  - 서류 보기: 미리보기, 페이지 수, 공유, 더 보기, **AI로 고치기**(AI 채팅), **내 프로필로 전환**
  - 내 프로필로 전환 시트: 기본 정보 · 소개 · 경력 · 기술 스택 중 반영할 항목을 고른다. 버튼은 "N개 항목 반영하기"이고, 경고 "지금 프로필의 소개와 경력은 이 내용으로 바뀌어요"를 보여준다.
- 내 활동: 칩 **지원활동 · 캘린더 · 북마크 · 팔로우 · 게시글**. 받은 제안은 마이 헤더 제안함에서 본다. 항목을 누르면 상세(shared route)로 이동한다.
  - 지원활동: "지원한 공고 N개". 배지는 **지원함 · 서류 · 면접 · 합격 · 불합격**(지원 단계를 사용자용 이름으로 바꿔 보여준다).
  - 캘린더: 8장 모바일 캘린더
  - 팔로우: 팔로잉 / 팔로워 탭
  - 게시글: 내가 쓴 글 / 댓글 단 글 탭

### 12.1 마이 헤더 버튼
- 마이의 세 탭(프로필·서류·내 활동) 모두 오른쪽 위에 같은 글래스 원형 버튼 2개를 둔다.
  - **제안함**(받은 편지 모양): 안 읽은 제안 수를 빨간 배지로 표시한다.
  - **설정**(톱니바퀴)

### 12.2 제안함
- 목록
  - 맨 위 글래스 세그먼트: "받은 제안 N" / "보낸 제안 N"
  - 항목: 보낸 사람 아바타·이름, 소속·직무, 메시지 미리보기 2줄, 시간, 상태 배지(받은 제안 **새 제안 · 수락함 · 거절함**, 보낸 제안 **읽지 않음 → 읽음 → 수락함 / 거절함**. 상대가 열어 보면 읽음이 된다)
  - 안 읽은 제안은 굵은 글씨에 보라색 점을 붙인다.
  - 하단 안내: "허브 프로필이 공개돼 있어야 제안을 받을 수 있어요."
- 상세
  - 보낸 사람 정보, "허브 프로필 보기" 칩, 제안 메시지, 받은 시각
  - **함께 보낸 공고** 카드(제안에 공고를 붙일 수 있다)
  - 보라색 카드 "답장 전에 이 공고에 맞춰 볼까요? · AI가 적합도를 보고 이력서를 고쳐 드려요" → AI 채팅으로 이동
  - 하단 버튼: **거절** / **수락하고 답장하기**
  - 수락하면 내 연락처가 그 사람에게 보인다(설정 › 허브 공개 › 연락처 기본값 "제안 수락한 사람만").
  - 수락하면 두 사람이 1:1 메시지로 대화를 시작한다. 답장은 첫 메시지가 되고, 이후 수락한 제안 상세에서 서로 메시지를 주고받는다. 보낸 사람도 보낸 제안 상세에서 같은 대화를 본다.

### 12.3 설정
마이 헤더 톱니바퀴에서 들어간다. 회색 그룹 카드와 글래스 뒤로 버튼을 쓰고, 스위치는 Push 보라색이며 켜고 끌 때 손잡이가 살짝 튄다.

| 묶음 | 항목 |
|---|---|
| 계정 카드 | 아바타, 이름, 로그인 방식("Google 계정으로 로그인" / "GitHub 계정으로 로그인") |
| 알림 (스위치) | 마감 임박 공고(북마크한 공고 마감 3일 전), 제안 받음, 댓글과 답글, AI 작업 완료(앱을 닫아도 끝나면 알려 드려요) |
| 일반 | 언어(한국어 / English). "앱 화면과 AI 답변 언어가 함께 바뀌어요." |
| 허브 공개 | 프로필 공개(스위치), 커리어 상태 공개 범위(모두에게 · 팔로워에게만 · 나만 보기, 기본 "모두에게") + "현재 회사 사람에게 숨기기", 연락처 공개 범위(기본 "제안 수락한 사람만") |
| AI 채팅 | 기본 말투(그대로 · 전문적인 · 자신감 있는 · 간결한 · 기술 중심 · 친근한, 기본 "그대로"), 대화 기록 보관 기간(요금제 한도 안에서 고른다. FREE 7일, ULTRA 무제한), 내 자료 읽기 허용(스위치. "내 서류와 북마크 공고를 AI가 읽어서 서류를 고쳐요. 끄면 매번 직접 첨부해야 해요."). 계정 모달 대화 설정과 겹친다(미결) |
| 기타 | 고객센터, 약관 및 정책, 로그아웃(빨간색) |

- 프로필 공개를 끄면 허브 목록에 나오지 않고 제안도 받을 수 없다.
- 커리어 상태 공개를 "나만 보기"로 하면 커리어 상태가 남에게 보이지 않고, 허브 목록과 커리어 상태 필터 결과에서도 빠진다.
- "현재 회사 사람에게 숨기기"를 켜면 같은 회사 이메일로 가입한 사용자에게 내 프로필을 숨긴다.
- 내 자료 읽기 허용을 끄면 AI 채팅이 내 서류와 북마크 공고를 자동으로 찾지 않는다(`@` 첨부만 가능).

### 12.4 푸시 알림과 알림함
- `expo-notifications`로 APNs(iOS)·FCM(Android) 토큰을 받아 서버에 등록한다. 로그아웃하면 토큰을 지운다.
- 처음 실행 후 알림이 필요한 시점(예: 첫 북마크, 첫 AI 작업)에 OS 권한을 요청한다.

| 종류 | 언제 | 누르면 |
|---|---|---|
| 마감 임박 공고 | 북마크한 공고 마감 3일 전(홈 "마감 임박 공고" 섹션의 7일 기준과 별개) | 채용공고 상세 |
| 제안 받음 | 누가 나에게 제안을 보냈을 때 | 제안 상세 |
| 댓글과 답글 | 내 게시물에 댓글, 내 댓글에 답글 | 게시물 상세 |
| AI 작업 완료 | AI 채팅 작업이 끝났을 때(앱을 닫아도) | 해당 대화 |

- 설정 › 알림 스위치로 종류별로 끈다. 꺼진 종류는 푸시도, 알림함 기록도 만들지 않는다.
- 알림함(홈 헤더 종 버튼): 위 4종류의 받은 알림 목록, 안 읽음 표시와 배지, "모두 읽음". 누르면 위 표의 화면으로 이동한다.
- 앱이 켜져 있을 때 온 알림은 배너 대신 배지만 올린다. 지금 보고 있는 대화의 AI 작업 완료는 알리지 않는다.

## 13. 모바일 UI 규칙 [M]

**디자인 방향**: 토스·당근·원티드 느낌의 Push 브랜드 UI에 iOS 글래스 컴포넌트를 최대한 쓴다. 그 회사들의 컴포넌트나 색을 그대로 가져오지 않는다.
- 크고 굵은 한글 제목, 넉넉한 여백, 둥근 회색 카드, 색이 꽉 찬 캡슐 CTA

## 15. AI 채팅 탭 [M]

채팅은 Claude Code가 일하는 방식을 모바일로 옮긴다. 이력서만이 아니라 Push 전체(공고, 지원, 캘린더, 허브, 제안, 글쓰기)를 다룬다. 탭 바는 대화 화면(`chat/[id].tsx`)에서만 숨기고, 첫 화면·빠른 시작 시트·대화 목록에서는 보인다. 앱 화면에는 페이즈 이름을 보여주지 않는다(디자인 캔버스 보드 제목에만 Phase 번호가 있다). 단계별(Phase) 보드 흐름과 최신 보드 흐름(할 일 5개를 바로 진행하고 승인은 diff 1회) 중 무엇을 기준으로 할지는 미결이다([PRD.md](PRD.md) 16장). 15.3은 단계별 보드 기준이다.

> 디자인 캔버스의 "인터랙티브 프로토타입"과 "모션" 보드는 예전 이름을 쓰는 구버전이다. 모션 타이밍 값(15.4)만 참고한다. 대화 제목은 "모아페이 백엔드 이력서"처럼 공고 기준으로 붙인다.

### 15.1 첫 화면
- 가운데에 흐린 "Push." 로고만 둔다. 제목, 인사말, 카드, 최근 대화, 바로가기는 없다.
- 왼쪽 위에는 슬라이드 바 버튼만 둔다. 새 대화(연필) 버튼은 첫 화면에서 숨기고 대화 화면에서 보인다.
- 입력창: 크고 둥근 입력창. 윗줄 안내 문구 "공고 링크를 붙여넣어 보세요", 아랫줄 + 첨부 · @ 언급 · 마이크 · 보내기
- 빠른 시작 알약 12개를 입력창 위에 가로 스크롤로 둔다(순서대로): 공고 링크로 맞추기 · 나에게 맞는 공고 찾기 · 부족한 점 찾기 · 적합도 보기 · 마감 임박 공고 정리 · 지원 현황 정리 · 캘린더 관리 · 허브 프로필 다듬기 · 경험 만들기 · 제안 답장 쓰기 · 커피챗 제안 쓰기 · 커리어 글 쓰기
- 빠른 시작을 누르면 재료 시트가 열린다. 내용은 빠른 시작마다 다르다. 재료가 다 차면 자동으로 만든 첫 메시지로 대화를 시작하고 탭 바를 숨긴다.
  - 마감 임박 공고 정리 시트: 공고마다 서류 상태(서류 없음 / 서류 준비됨 / 초안 있음)
  - 나에게 맞는 공고 찾기 시트: 옵션 "적합도 7점 이상인 공고만"
  - 지원 현황 정리 시트: "진행 중 N / 전체 N"
  - 예: 캘린더 관리 시트 — 이번 주 일정 3건, 할 일 4가지(이번 주 정리하기(기본) · 마감일 넣기 · 면접·커피챗 잡기 · 준비 알림 만들기), Google 캘린더 연결 상태, "이번 주 정리하기" 버튼

### 15.2 진행 표시 (Claude Code 방식)
| 요소 | 동작 |
|---|---|
| `✻` 상태 줄 | 입력창 위 작은 글래스 알약. 도는 기호, 몇 초마다 바뀌는 동사("맞춰보는 중…", "훑어보는 중…"), 경과 시간. 작업 중에는 보내기 버튼이 검은 중지 버튼으로 바뀐다 |
| `●` 도구 줄 | 실행 중엔 깜빡이고 끝나면 초록. 예: "공고 읽기 모아페이 · 백엔드 엔지니어" |
| `⎿` 결과 줄 | 들여쓴 한 줄 요약. 길면 "+N줄"로 접고 누르면 펼친다 |
| `☐` 할 일 | "할 일 2/5". 진행 중 항목은 굵게, 완료는 체크와 취소선. 중간에 요청이 오면 "새로 추가" 항목이 붙는다 |
| `±` diff | 이력서 수정 내용을 빨강 −, 초록 + 줄로 보여준다 |
| `1·2·3` 승인 패널 | 입력창 자리에 올라온다. iOS는 떠 있는 글래스 시트. 예: 1 네, 반영해 주세요 / 2 네, 이번 대화에선 묻지 않기 / 3 아니요, 다르게 해 주세요. "번호를 누르거나 바로 말해도 돼요" |
| `■` 중단 | 중지하면 실행 중 줄이 빨간 점과 "중단됨 · 어떻게 할지 알려 주세요"로 멈춘다. 다시 말하면 이어서 한다 |
| `@` 언급 | "@"를 치면 입력창 위에 북마크 공고 · 마이 › 서류 · 내 링크 · 바로가기 제안이 뜬다. "@" 뒤에 글자를 치면 그 글자가 들어간 항목만 남기고, 결과가 없는 묶음은 숨긴다 |

- 작업 중에 보낸 메시지는 "대기 중"으로 쌓인다.
- 끝나면 "N분 N초 동안 작업했어요"를 표시한다.
- "생각함 · N초"처럼 생각한 시간을 접어서 보여준다.

### 15.3 단계별 화면
| 단계 (보드 이름) | 화면 |
|---|---|
| 진행 방식 고르기 (Phase 0) | 1 지금 이력서로 공고에 맞춰 고치기 · 2 필요한 프로젝트 경험까지 만들기 · 3 직접 말하기 |
| 산출물과 자료 확인 (0-I) | 산출물 체크(이력서·포트폴리오·자소서), Push에서 찾은 자료(내 서류·북마크 공고·이력서 속 GitHub, 각각 변경), 말투 칩(그대로·전문적인·자신감 있는·간결한·기술 중심·친근한), "이대로 진행" |
| Push 자료 고르기 (0-I) | 마이 › 서류, 북마크 공고 목록 시트. "다른 곳에서": 파일 · GitHub 링크 · 공고 붙여넣기 |
| 분석 시작 확인 (0-I→1) | 입력 정리 결과 줄 + 1 네, 시작 / 2 자료 바꾸기 / 3 그만 |
| 입력 분석 중 (1) | 이력서 읽기, GitHub 살펴보기(이력서에 없는 저장소를 찾으면 알려 줌), 공고 읽기 |
| 적합도 확인 (1→2) | 5개 항목(기술 스택·경험 연관성·경력 수준·키워드·도메인), 10점 만점과 별점, 키워드 칩. 1 맞춰서 고치기 / 2 피드백만 / 3 점수만 |
| 수정 전략 (2) | 섹션별 강화·수정·추가·축소와 이유, 추가할 키워드 |
| 경험 만들기 방식 (2-X) | 일부러 병목 넣기(L1 가벼운·L2 중간·L3 극한), 문제 예방(성능·보안·안정성·데이터 무결성·확장성). 여러 개 선택 |
| 프로젝트 기획서 고르기 (2-X) | 방향 검증 5개 기준, 기획서 4개(통과·조건부 배지). "기획서만 받기" / "1개 시작" |
| 초안 쓰는 중 (3) | 섹션별 할 일과 커서가 깜빡이는 초안 미리보기 |
| 초안 검토 (3) | v1 파일, 바뀐 점 diff. 1 좋아요 / 2 고쳐 주세요. 수정은 3번까지 |
| 점수 올리기 (3-C) | 회차별 결과 줄, 6.9 → 8.3 점수 카드, 목표 8.0. 품질 검사로 / 한 번 더(최대 5번) |
| 품질 검사 (4-A) | 오타·문법·말투·ATS. 바로 고친 것은 diff, 추천 수정은 체크해서 반영 |
| 템플릿 고르기 (4-B) | 심플(추천)·모던·크리에이티브·ATS, 프로필 사진 넣기(모든 템플릿) |

| 예외 | 재시도한 단계(주황 점), 읽지 못한 공고(빨간 점, 예: 로그인 필요 영역). 1 공고 붙여넣기 / 2 이대로 진행 / 3 Push 공고에서 고르기 |
| 완료 | 결과 요약(적합도 6.9 → 8.1, 바꾼 점 목록), PDF 카드, "{회사}에 바로 지원하기", "내 서류에 저장"(저장 위치 표시 "마이 › 서류") |

### 15.4 모션 스펙
| 동작 | 값 |
|---|---|
| 상태 줄 | 기호 1.1s · 6프레임, 동사 2.5s마다 교체, 시머 2s linear |
| 도구 실행 → 완료 | 깜빡 1s, 완료 300ms 팝, 결과 페이드 250ms |
| 할 일 체크 | 체크 350ms 오버슛, 취소선 350ms, 다음 항목 즉시 굵게 |
| 긴 결과 펼침 | 250ms ease-out, 높이 + 페이드 |
| diff | 줄당 300ms, 150ms 간격 |
| 승인 패널 | 올라옴 420ms `cubic-bezier(.2,.9,.25,1)`, 선택 150ms |
| 중단 | 누름 120ms, 전환 즉시, 입력창 바로 활성 |
| 메시지 보내기 | 400ms `cubic-bezier(.2,.9,.25,1.15)`, scale .94 → 1, 오른쪽 아래 기준 |
| @ 언급 | 제안 목록 250ms, 선택 이동 200ms |

- 햅틱: 승인 패널이 올라올 때 가벼운 진동, 작업 완료 시 성공 진동, 중단·오류 시 경고 진동
- 동작 줄이기: 이동과 확대는 페이드로 바꾸고, 시머와 기호 회전은 멈춘다. 경과 시간은 계속 올라간다.
- 스크롤: 새 줄이 생기면 아래로 따라간다. 사용자가 위로 올리면 멈추고 "↓ 새 내용" 버튼을 띄운다.
- iOS와 Android가 같은 값을 쓴다.

### 15.5 대화 화면
- 헤더: 왼쪽 슬라이드 바 버튼, 가운데 대화 제목, 오른쪽 글래스 캡슐(새 대화 연필 · ⋯)
- ⋯ 메뉴: 이름 바꾸기 · 쓴 서류·공고 보기 · 대화 공유 · 대화 삭제
- 비밀 대화는 없다.

### 15.6 슬라이드 바와 계정
- 슬라이드 바: 화면 전체 폭으로 탭 바까지 덮는다.
  - 왼쪽 위 사용자(사진 · 이름 · PRO), 오른쪽 위 » 글래스 닫기 버튼. 사용자 영역을 누르면(눌린 동안 회색) 계정 모달이 열린다.
  - 메뉴: 새 대화 · 내 서류 · 내 링크 · 북마크한 공고. 내 서류 · 내 링크 · 북마크한 공고는 **계정 모달과 같은 모달**(거의 전체 높이, 왼쪽 위 ✕ 닫기)로 열린다.
  - 최근 대화(날짜로 묶지 않음)와 "모두 보기" 글자 버튼
- 내 서류 모달: 마이 › 서류와 같은 목록. 오른쪽 위 + 로 파일을 올린다.
- 내 링크 모달: 두 종류의 링크를 모은다.
  - 공고 링크: AI 채팅에 붙여넣거나 쓴 외부 공고 링크(회사 채용 페이지, 채용 사이트)
  - 내 프로필 링크: GitHub · 포트폴리오 · 블로그 등
  - 위쪽 칩: 전체 N · 공고 · GitHub · 포트폴리오 · 블로그 · 기타. 목록은 종류별로 묶는다(공고 N, GitHub N, 포트폴리오 · 블로그 N).
  - 항목: 제목, 주소. 상태 표시 — 공고는 "맞춤 N회" · "읽음" · "읽는 중", 그 밖은 "프로필" · "저장소" 같은 종류
  - 항목 오른쪽 ⋯ 메뉴: 열기 · 링크 복사 · AI 채팅에서 쓰기 · 삭제(빨간색)
  - 하단 안내: "AI 채팅에서 @언급으로 불러오거나, 서류를 고칠 때 근거로 써요."
  - 빈 상태: 링크 아이콘, "아직 모아 둔 링크가 없어요", 설명 한 줄, "링크 추가" 버튼, 종류 칩(공고 · GitHub · 포트폴리오 · 블로그)
  - 링크 추가 시트(모달 위에 뜸): 링크를 붙여넣으면 종류를 자동으로 고른다. 스위치 "추가하면 AI가 README와 커밋을 읽어 둬요", "추가하기" 버튼
- 북마크한 공고 모달: 칩 전체 N · 마감 임박 N · 지원 안 함 N, 공고 목록. 안내 "공고를 누르면 상세를 보거나 그 공고에 맞춰 대화를 시작할 수 있어요."
- 전체 대화 목록: 오늘 / 이번 주로 묶는다. 항목마다 상태 배지("확인 필요" · "작업 중")와 마지막 진행 줄을 보여준다. 대화 검색이 있다.
- 계정 모달: 거의 전체 높이 시트. × 버튼, 제목 "계정", 톱니바퀴 없음

  - 대화: 답변 말투, 작업 강도, 바꾸기 전에 확인(스위치), 대화 기록 보관
