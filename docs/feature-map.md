## 2. 데스크톱 (fo-desktop, 기존)

```
로그인 (/login) ─ OAuth ─ /auth/callback
앱 셸 (좌측 사이드바: 기능 / 채팅 / 프로젝트)
├─ 홈 (/) ─ AI 명령창, 새 대화
├─ 채팅 (/chat/:id) ─ 스트리밍, 승인 카드, 문서 카드
├─ 기능
│  ├─ 지원 현황 (/applications) ─ 단계, 타임라인, 제출
│  │  └─ 공고 상세 (/jobs/:id) ─ 요구사항, 갭 분석
│  ├─ 내 서류 (/documents) ─ 문서 편집기 (/documents/:id): TipTap, AI 버블, 확정, PDF/DOCX
│  ├─ 캘린더 (/calendar) ─ Google 연동 (/integrations/google/callback)
│  └─ 면접 준비 (/interview) — 추후
├─ Career Vault (/vault) — 추후
└─ 설정 (/settings) ─ 요금제 (/settings/plan), AI 키, 언어·테마
```

## 3. 모바일 (fo-mobile, 신규)

```

│  └─ 전화번호 입력 · 6자리 인증 (OAuth 뒤에도 거침) ─ 참고 데이터 동의(선택, 기본 꺼짐)

   ├─ 홈

   │     ├─ 툴바: 북마크 · 공유 (글래스 캡슐)

   │     └─ 하단: AI로 맞추기 → AI 채팅 · 지원하기 → 서류 고르기 시트(AI로 맞춘 서류 / 원본 · 포트폴리오 함께) → 지원 완료

   │  ├─ 검색창(이름, 직무, 기술 검색) ─ 허브 안에서 사람을 찾는다 (통합 검색 아님)

   │  ├─ 추천 프로필 리스트

## 4. fo-web — 개인·기업 웹

fo-mobile의 웹 버전이다. 개인은 AI 채팅만 뺀 모바일과 같은 Push를 쓴다. 기업은 사업자 확인 후 공고·지원자를 관리하고 기업 AI를 쓴다. 규칙은 [feature-spec.md](feature-spec.md) 16·17장에 있다. 웹 라우트 이름과 레이아웃은 Claude Design "웹" 페이지 기준으로 정한다.

아래 두 화면은 모바일 앱 WebView에서도 쓴다.

| 라우트 | 내용 | 호출 |
|---|---|---|
| `/postings/:id` | 회사 헤더, 적합도(앱 WebView에서만. 웹 브라우저에서는 없음), 직무 설명, 자격 요건, 우대 사항, 근무 조건, 원문 보기 링크 | `GET /postings/{id}` (백엔드 미확정) |
| `/profiles/:id` | 프로필 헤더, 소개, 커리어 상태, 경력 타임라인, 기술 스택 | `GET /profiles/{id}` |

앱 WebView에서는 버튼이 없다(네이티브 헤더와 툴바가 맡는다). 웹 브라우저에서는 툴바와 하단 버튼을 웹이 그린다.

### 4.1 개인 웹

```
로그인 (개인 / 기업 선택) ─ 개인: Google · GitHub · 전화번호 ─ 전화번호 인증 · 참고 데이터 동의(선택)
├─ 홈 ─ 공고 섹션(새로 올라온 · 마감 임박 · 많이 본) [비로그인 가능]
├─ 채용공고 페이지 ─ 필터 · 정렬 · 그리드 [비로그인 가능]
├─ 통합 검색 ─ 공고 · 사람 · 게시글 [비로그인은 공고만]
├─ 채용공고 상세 [비로그인 가능] ─ 북마크 · 공유 · 지원하기 → 서류 고르기 → 지원 완료 (적합도 없음, 비로그인이면 로그인 후 복귀)
├─ 허브 ─ 허브 프로필 상세 ─ 팔로우 · 제안하기
├─ 소셜 ─ 게시물 상세 · 글쓰기
├─ 마이
│  ├─ 프로필
│  ├─ 서류 ─ 파일 업로드 (AI로 만들기·고치기 없음)
│  └─ 내 활동 ─ 지원활동(적합도 점수만) · 캘린더 · 북마크 · 팔로우 · 게시글
├─ 제안함 ─ 1:1 메시지
├─ 알림함
